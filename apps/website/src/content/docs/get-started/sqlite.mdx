vola runs on PostgreSQL or on a single SQLite file. On SQLite the server needs Node 24 and a local disk, nothing else: no Docker, no database service, no Redis. The driver is Node's built-in `node:sqlite`, and the `vola` command line opens the same file directly.

<Aside type="note" title="Since 1.1.0">
SQLite support is in 1.1.0 and later ([Changelog](/packages/changelog/)): the `@vol-a/*` packages and the image `ghcr.io/digital-cube/jsvola:1.1.0`. `@vol-a/server` 1.0.1 refuses a `file:` URL.
</Aside>

## What SQLite gives up

Every route, answer and error code is the same as on PostgreSQL, and so are the four encryption modes, real-time lists, the CLI and the OCR search. What changes is how far it scales:

- **One server process on the file, on one host.** Your own application counts as that process when it [embeds the plugin](/get-started/embedded/). For more than one server, use PostgreSQL.
- **At most one worker, on the same host.** Add Redis and run `node node_modules/@vol-a/server/dist/worker.js` with the same variables to take thumbnails off the request path and to get OCR.
- **The file on a local disk.** Never on NFS or SMB; the storage directory can be, the database cannot.

[Files and storage](/concepts/files-and-storage/#postgresql-or-sqlite) has the features by database, and the [SQLite guide](/reference/sqlite/) has the rest: the worker, backups with `VACUUM INTO`, restores, upgrades and what not to do with the file.
