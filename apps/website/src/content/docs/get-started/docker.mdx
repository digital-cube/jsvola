The repository's `docker-compose.yaml` is a production-like stack: the vola server, its worker, PostgreSQL and Redis, with health checks and named volumes. The server applies its migrations when it starts, and the `vola` command line is inside the image.

<Steps>

1. Get the compose file, with the rest of the repository:

   <Code code={clone} lang="sh" />

2. Give the database a password:

   <Code code={env} lang="sh" />

3. Build and start it, then wait until the server says it is ready. The first build takes a few minutes:

   <Code code={up} lang="sh" />
   <Code code={upOut} lang="txt" title="What it printed" />

4. Make a tenant and an API key for it. The key is printed once; only its SHA-256 is stored:

   <Code code={key} lang="sh" />
   <Code code={keyOut} lang="txt" title="What it printed" />

5. Upload a file to an instance of your application, here a ticket, and read part of it back:

   <Code code={upload} lang="sh" />
   <Code code={uploadOut} lang="txt" title="What it printed" />

6. When you are done, stop it and delete its data:

   <Code code={down} lang="sh" />

</Steps>
