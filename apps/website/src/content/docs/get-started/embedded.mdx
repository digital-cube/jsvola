## Pick the database

`VOLA_DATABASE_URL` decides: `postgresql://…` for PostgreSQL, `file:<path>` for one SQLite file. `connect()` picks the driver from the URL, and `runMigrations()` brings the database up to date, creating the SQLite file on the first start. On SQLite your application **is** the one server process the file allows: do not also run `server.js` on it. `vola` CLI commands next to it are fine, and a worker on the same host is too. `connect()` opens one database per process. The `onClose` hook closes it, so after a clean stop only `app.db` and `storage` remain. The rest is in [Run it on a SQLite file](/get-started/sqlite/) and the [SQLite guide](/reference/sqlite/#embedded-the-plugin-in-your-application).

## Things to run beside it

**The worker is a separate process.** With `VOLA_REDIS_URL` set, thumbnails and OCR are rendered off the request path, so without a worker `/thumb` keeps answering 202. Without Redis, thumbnails render inline on `/thumb` and OCR does not run. Run `node node_modules/@vol-a/server/dist/worker.js` with the same environment. It needs `VOLA_REDIS_URL`, the same `VOLA_DATABASE_URL` and `VOLA_STORAGE_PATH` and, for encrypted files, the same key file. On SQLite it must run on the same host, opening the same file. PDF thumbnails and OCR need `pdftoppm` and `tesseract` on the machine.

**Options you can pass.** Besides `prefix`, `config` and `db`, the plugin takes `redis`, `storage`, `events`, `audit`, `encryption`, `decorateRow` and `extend`. The [package README](https://github.com/digital-cube/jsvola/blob/main/packages/server/README.md) describes them.
